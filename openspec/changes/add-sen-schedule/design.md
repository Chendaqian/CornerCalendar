## Context

CornerCalendar 当前把内置中国日历和用户 ICS 聚合为普通 `CalendarEvent`，日期格只区分普通事件点、法定节假日“班/休”和蓝色选中圆圈。森日程的真实输入是用户提供的 Markdown 表格，每张表代表一个版本迭代，并额外携带由序号约定的 TR、角标和阶段圆圈语义。

本变更不把森日程伪装成 ICS，也不增加远程源。它需要一个小型、严格的 Markdown 表格导入器，将输入转成持久化结构化模型，再在 ViewModel 层与现有日历只读合并。

## Goals / Non-Goals

**Goals:**

- 用户只需输入迭代名称并粘贴现有 Markdown 表格即可导入。
- 一张表对应一个迭代，多张表可以并存和独立更新/删除。
- 自然日总天数从日期闭区间计算，工作天数排除周末和“休”，计入普通工作日及“班”。
- 角标、阶段圆圈、蓝色选中态和“班/休”在固定日期格中稳定共存。
- 悬浮提示明确指出活动属于哪个迭代。

**Non-Goals:**

- 不支持森日程 ICS、URL、网络同步或公司系统双向同步。
- 不提供 Markdown 富文本编辑器、甘特图、资源排期或活动逐行编辑。
- 不把表格工作量强行当作工作天数，也不提供复杂的自定义工作日历编辑。
- 不从活动名称猜测特殊规则；规则只按标准表格序号解析。

## Decisions

### 1. 设置页使用“名称 + Markdown”直接导入

“森日程”分类包含：全局显示开关、必填的单行迭代名称文本框、用于粘贴表格的多行文本框、“导入/更新”按钮，以及已导入迭代列表。列表显示名称和日期范围，并提供删除命令。

导入后立即解析并保存结构化数据，原始 Markdown 不参与运行时渲染。同名导入替换该迭代的活动，便于排期调整；不同名称始终新增，因此 `v2.24迭代`、`v2.25迭代` 等可同时存在。

选择文本框粘贴而不是文件或 ICS，是为了匹配内部表格的实际流转方式，并把实现限定为纯本地数据处理。

### 2. 使用严格的五列表格解析器

解析器在粘贴文本中定位以下表头及其分隔行：`序号`、`活动`、`工作量(天)`、`开始时间`、`结束时间`。它逐行读取 Markdown 单元格，支持首尾竖线、空白和转义竖线，并执行以下验证：

- 序号必须为正整数且在同一表中唯一。
- 活动不能为空。
- 工作量必须为正整数或 `-`；`-` 保存为无工作量。
- 日期接受用户样例的 `yyyy/M/d` 格式，结束日期不得早于开始日期。
- 表格必须至少有一行有效活动；任一行错误时整次导入失败并定位行号，不保存半张表。

结构化模型包含迭代 ID、用户输入名称和活动集合；活动包含序号、标题、可空工作量、开始/结束日期。迭代 ID 独立于名称，设置更新以名称匹配，JSON 继续由 `AppSettings.Current` 原子保存。

### 3. 固定序号映射特殊语义

标准迭代表按序号应用下列规则：

| 序号 | TR 归属 | 常规角标 | 末日角标 | 圆圈分组 |
| --- | --- | --- | --- | --- |
| 1 | TR1 | R1 | - | TR1 |
| 2 | TR2 | R2 | - | TR2 |
| 3 | TR3 | R3 | - | TR3 |
| 4 | TR4 | R4 | - | TR4 |
| 5 | - | 宣 | - | TR5 |
| 6 | TR5 | R5 | - | TR5 |
| 7 | TR5 | 反 | - | TR5 |
| 8 | TR5 | R5 | - | TR5 |
| 9 | TR5 | R5 | - | TR5 |
| 10 | - | 编 | 提 | CODING |
| 11 | - | 测 | - | TESTING |
| 12 | - | 上 | - | RELEASE |
| 13 | - | 巡 | - | RELEASE |
| 14 | - | 总 | - | RELEASE |

序号 5 只借用 TR5 圆圈颜色，不纳入 TR5 总天数；TR5 总天数仍按序号 6–9 计算。未知序号可作为普通森活动出现在提示和近期事件中，但没有特殊角标或圆圈，避免未来附加行导致整表无法导入。

### 4. 自然日和工作天按日历规则计算

Markdown 的开始、结束日期均为包含关系。单个活动自然日数为 `结束日期 - 开始日期 + 1`；TR 总天数按同一迭代和 TR 下全部活动覆盖日期的并集计数，避免重叠行重复计算。工作天数按日期逐日判断：周六日默认排除，中国日历标记“班”时计入，标记“休”时排除。表格中的工作量仍保留在结构化活动中，但紧凑悬浮提示展示计算出的工作天数。

用户样例的序号 1–14 自然日数依次为 2、3、4、2、1、5、1、1、1、24、25、1、1、1 天；TR3 覆盖 2026/7/31–2026/8/3，共 4 个自然日、2 个工作日；TR5（序号 6–9）覆盖 2026/8/20–2026/8/27，共 8 个自然日。

### 5. 森日程与基础日历在 ViewModel 层合并

`AppSettings` 新增默认 `false` 的全局开关和已导入迭代集合。ViewModel 仅在开关开启时把覆盖查询范围的森活动转换为显示事件并加入月历/近期事件；关闭时不改变普通 ICS 和中国日历服务。

设置页开关和主窗口“森”按钮读写同一设置。主窗口点击立即保存并异步刷新当前月历与近期事件；不执行网络刷新。

### 6. 圆圈按阶段、角标字体按自身语义着色

日期格新增位于日期数字后的阶段圆圈层和位于左上角的森角标层；“班/休”继续位于右上角。森角标尺寸为 18×18，使用背景遮罩阶段圆圈以保持字形清晰。阶段圆圈只显示在普通工作日，周末、“班”和“休”日期不显示；圆圈颜色来自活动的圆圈分组：TR1–TR5、CODING、TESTING、RELEASE 共八个阶段色。

基础角标 R1–R5、编、测、上与对应阶段圆圈共享颜色。宣、反、提、巡、总拥有专属颜色；同一活动同时存在阶段色和专属角标色时，角标字体优先使用自己的颜色，圆圈不跟随专属角标改变。这同时满足阶段识别和每种角标独立颜色要求。

现有今日和蓝色选中圆圈位于更高视觉层。选中森日期仍显示蓝色选中圆圈；森角标和提示继续提供阶段信息。关闭森日程时角标和阶段圆圈一起消失。

同一天命中多个迭代时，日期格按“末日提测优先、导入列表顺序、活动序号”选择一个主角标和圆圈，提示按迭代列出全部命中活动。阶段提示使用 `TR3（技术架构设计评审）自然 4 天，工作 2 天` 的紧凑格式；TR5 等阶段下再列出当前活动。每条提示先显示用户输入的迭代名称，例如 `v2.24迭代`。

### 7. 窗口与内部布局等比放大

日历主窗口、日期详情、天气和日期选择窗口使用 1.1 的 `LayoutTransform`，并将窗口外框尺寸同步放大 10%；设置窗口保持原尺寸。布局变换作用于根内容而非单独字号，因此日期格、按钮、间距、边框和文本保持同一比例，避免日期文字变大后发生局部遮挡。

日期详情窗口保存当前展示日期：再次点击同一日期时隐藏窗口，点击其他日期时复用窗口并刷新内容。天气摘要使用同样的显示切换语义，天气窗口通过独立的左侧定位方法与主窗口顶部对齐，并在空间不足时临时落到主窗口右侧或工作区边界内。周末、“班”和“休”日期同时隐藏阶段圆圈与森角标。

## Risks / Trade-offs

- [用户粘贴的表头或单元格格式不正确] → 严格校验并显示具体行号和原因，不做静默猜测或部分导入。
- [同名导入意外覆盖] → 按钮明确命名为“导入/更新”，命中已有名称时在保存前确认替换。
- [多个迭代日期重叠导致日期格空间不足] → 日期格只显示一个确定性主角标和圆圈，提示完整列出所有迭代活动。
- [专属角标色与阶段圆圈不同] → 这是“角标优先使用自己的颜色”的明确规则；基础角标仍与阶段圆圈统一。
- [主题对比不足] → 所有颜色集中放入 Light/Dark 资源并进行人工视觉检查。

## Migration Plan

1. 新设置字段使用向后兼容默认值，旧 `settings.json` 加载后森日程关闭且迭代列表为空。
2. 不迁移、不读取现有普通 ICS 配置；用户在森日程文本框中首次导入 Markdown。
3. 发布前用用户提供的 14 行表格验证解析、总天数和全部视觉映射，并运行完整构建与测试。
4. 回滚时移除森日程模型和 UI；旧版本会安全忽略设置 JSON 中的新增字段。

## Open Questions

无。已确认一张 Markdown 表格对应一个迭代，迭代名称由用户文本输入；序号 5 使用 TR5 圆圈但不加入 TR5 天数，序号 12–14 共用上线阶段圆圈，蓝色选中态始终优先。
